# TrustGraph-V2X

**Trust-Aware Spatio-Temporal Graph Learning for Predictive Handover and RSU Load Balancing in 5G-V2X Networks**

Resume title: **TrustGraph-V2X — Deep-Learning-Based Predictive Mobility and Load Management for 5G Vehicular Networks**.

## Midsemester presentation package

After generating the local package, double-click **Open-Midsem.cmd** for the offline demonstration or **Open-Slides.cmd** for the presentation. It contains a real SUMO mobility replay, clean and attacked synthetic network replays, measured model outputs, explanations of handover/fallback decisions, held-out results, browser slides with speaker notes, and a printable report.

This repository includes the application and presentation source. Generated datasets, model checkpoints, the `midsem/` folder, PDF/ZIP exports, installed dependencies and local settings are intentionally excluded. A fresh clone must run the setup and generation commands below before opening the demonstration.

Read [the eight-minute demonstration guide](docs/MIDSEM_DEMO_GUIDE.md) before presenting. The replay seed is fixed, scores come directly from the saved checkpoint, and ground truth appears only as an evaluation overlay. The package does not claim real Simu5G integration or consistent model superiority.

After installing the project, generate the required artifacts and presentation (training may take several minutes):

```powershell
.\.venv\Scripts\python.exe -m trustgraph sumo --output outputs/sumo
.\.venv\Scripts\python.exe -m trustgraph demo --config configs/default.json --output outputs/demo
.\.venv\Scripts\python.exe -m trustgraph midsem --output midsem
```

If `outputs/sumo` and `outputs/demo` already contain completed runs, use only the final command to rebuild the presentation. Dataset generation refuses to overwrite an existing experiment.

Vehicles report mobility and radio observations. A temporal graph model predicts serving-link degradation, future cell load, and suspicious telemetry. A controller uses these predictions to choose handover targets. The trust-aware model attenuates vehicle messages before graph aggregation.

## Installation and running on Windows

Open PowerShell in the `TrustGraph-V2X` folder and create a local environment:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[sumo,dev]"
```

Then run a new experiment or the tests:

```powershell
# Real traffic simulation and mobility collection
.\.venv\Scripts\python.exe -m trustgraph sumo --output outputs/sumo-new

# Generate 12 independent runs, train both models, evaluate four policies
.\.venv\Scripts\python.exe -m trustgraph demo --config configs/default.json --output outputs/demo-new

# Run verification
.\.venv\Scripts\python.exe -m pytest -q
```

Choose a new dataset output folder for each experiment; dataset creation refuses to overwrite an existing manifest. The presentation builder expects completed runs under `outputs/sumo` and `outputs/demo`, generated by the commands above.

To see cars, add `--gui` to the SUMO command. GUI mode runs at approximately real time so that departures, stops, acceleration and turns are visible. The green plus-shaped object is the generated four-way intersection. The headless run creates a reusable scenario under `outputs/sumo-new/scenario/`.

Linux/WSL uses `.venv/bin/python` in place of `.venv\Scripts\python.exe`. Exact versions from the verified environment are recorded in `requirements-lock.txt`.

## Individual pipeline commands

```powershell
.\.venv\Scripts\python.exe -m trustgraph generate --output data/experiment-01 --runs 12 --config configs/default.json
.\.venv\Scripts\python.exe -m trustgraph train --data data/experiment-01 --output outputs/baseline --baseline
.\.venv\Scripts\python.exe -m trustgraph train --data data/experiment-01 --output outputs/trustgraph
.\.venv\Scripts\python.exe -m trustgraph evaluate --config data/experiment-01/config.json --baseline outputs/baseline/model.pt --trust outputs/trustgraph/model.pt --output outputs/comparison
.\.venv\Scripts\python.exe -m trustgraph predict --checkpoint outputs/demo/trustgraph/model.pt --observations outputs/demo/dataset/run_00053.observed.npz --output outputs/prediction.json
.\.venv\Scripts\python.exe -m trustgraph serve --checkpoint outputs/demo/trustgraph/model.pt
```

`train` defaults to the trust-aware model; `--baseline` disables sender-trust gating while retaining the same prediction heads and architecture. `serve` listens only on `127.0.0.1:8765`; see [the adapter contract](docs/SIMULATOR_INTERFACE.md).

## Data and model definitions

- A run stores observed telemetry in `*.observed.npz` and attack labels/actual positions separately in `*.truth.npz`. The graph builder never reads truth fields.
- Entire runs are split 60%/20%/remainder before creating sequences. The default 12 runs produce 7 training, 2 validation and 3 test runs. Fixed physical scales normalize features without fitting on test data.
- Binary losses use positive-class weights computed only from training labels (capped at 20). Weighted sigmoid outputs require calibration before interpreting them as reliable probabilities.
- Ten observations at 100 ms spacing span 0.9 seconds from first to last. The future horizon is the next 10 steps (1 second).
- A bad link means SINR below 8 dB for at least three consecutive future samples. This is an operational degradation label, not a standards-based radio-link-failure event. Labels are masked when the serving cell changes inside the horizon.
- Load is connected vehicles divided by the toy cell capacity; it may exceed 1. The load head predicts the horizon endpoint. This proxy must be replaced with measured resource utilization for real 5G experiments.
- The attack head estimates currently corrupted telemetry, not permanent attacker identity. False-position attacks start at sample 15. A trusted receiver supplies candidate radio measurements in the toy threat model.
- The bipartite graph has vehicle and cell nodes, with SINR, reported distance and serving status on each edge. Dense masked aggregation is used instead of PyG for these small graphs.
- A local vehicle GRU predicts attack probability before aggregation. Trust is `1 - attack_probability`; it gates outgoing vehicle messages. Updated cell context feeds the vehicle GRU, so trust can influence both link and load predictions.
- The serving-link risk head is **not** used as if it predicts risk for every candidate. Candidate selection uses observed SINR and predicted cell load.
- The fallback confidence gate uses `abs(2*p_risk - 1)`, an uncalibrated certainty heuristic. Calibration and out-of-distribution detection are required before making reliability claims.

## Evaluation outputs

`baseline/metrics.json` and `trustgraph/metrics.json` include epoch losses, held-out link/attack precision, recall, F1 and AUROC, plus load MAE/RMSE. AUROC is null for a single-class test target.

`evaluation/closed_loop.csv` contains matched-seed runs for reactive, load-aware heuristic, ordinary temporal GNN and TrustGraph controllers at 0%, 10% and 30% attacked vehicles. `summary.json` includes means and sample standard deviations. Network outputs include a delivery proxy, bad-link samples, overload cell-seconds, handover count, ping-pong count, load fairness and inference latency. **Delivery proxy is not measured packet delivery ratio.** The load-aware heuristic is not a QASP implementation.

  sumo.py          Real SUMO scenario and TraCI collector
  simulation.py    Synthetic physical state, attacks and telemetry
